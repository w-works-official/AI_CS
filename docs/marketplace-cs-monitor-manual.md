## 1. 이 스킬로 할 수 있는 일 {color="blue"}
`marketplace-cs-monitor`는 확인된 로그인 브라우저 세션을 이용해 아래 7개 CS 채널을 한 번에 점검합니다.

수집 결과는 마스킹·중복 제거 후 운영자가 설정한 `Pink Rocket CS 운영 데이터 v1` 시트에 저장하고, 답변이 필요한 건에는 기존 사람답변 라이브러리를 근거로 AI 초안을 준비할 수 있습니다.
## 2. 사용 전 준비 {color="green"}
- [ ] 스마트스토어·카카오스타일·에이블리 판매자 계정이 로그인된 브라우저를 확인합니다. 현재 기본은 Google Chrome입니다.
- [ ] 이 노트북은 Whale과 Chrome을 병행 사용하므로, 프롬프트에서 지정한 브라우저의 실제 앱·프로필·URL·로그인 상태를 확인합니다. 이전 혼선은 이 기기의 병행 사용 문제이며 Whale 자체가 불가능한 것은 아닙니다.
- [ ] CAPTCHA, 2단계 인증, 계정 재확인이 보이면 사용자가 직접 완료합니다.
- [ ] 처음 사용할 때는 마켓별 판매자 화면을 한 번 열어 로그인 상태를 확인하면 가장 안정적입니다. 탭을 미리 열어두지 않아도 로그인 세션이 살아 있으면 직접 이동할 수 있습니다.
- [ ] 수집 중에는 운영자가 같은 문의에 답변하거나 상태를 바꾸지 않는 것이 좋습니다.
<callout icon="⛔" color="red_bg">
	**절대 자동으로 하지 않는 것**
	답변 전송 · 상담완료 · 문의유형 변경 · 취소 · 환불 · 교환 · 주문변경 · 고객메모 수정 · 로그인정보 입력은 수행하지 않습니다. `AUTO_SEND`는 항상 비활성화합니다. 톡톡 상세 확인에 따른 미읽음→읽음 전환만 예외적으로 허용합니다.
</callout>
## 3. 가장 쉬운 사용 순서 {color="green"}
1. 이번 실행에 사용할 브라우저에서 필요한 마켓 로그인이 유지되는지 확인합니다.
2. Codex의 아무 작업에서 추천 프롬프트를 붙여 넣습니다. 이 스킬은 전체 설치되어 있으므로 현재 프로젝트 폴더가 달라도 사용할 수 있습니다.
3. Codex가 지정한 브라우저의 실제 앱·프로필과 채널을 확인하고 운영상 읽기 전용으로 수집합니다.
4. 로그인 만료·CAPTCHA·2단계 인증이 나오면 해당 화면에서 멈추므로 직접 처리한 뒤 다시 진행을 요청합니다.
5. 완료 보고에서 채널별 건수, 신규·변경·미응답 건수, 실패 채널, AI 초안 수를 확인합니다.
6. 실제 답변 전송 전에는 내부 CS 운영 데스크 또는 쇼핑몰 원문 화면에서 사람이 최종 확인합니다.

## 5. AI 추천답변이 만들어지는 방식 {color="purple"}
1. 답변이 필요한 문의만 `NEEDS_REPLY`로 구분합니다.
2. 구글시트 `06_ANSWER_LIBRARY`에서 질문과 가까운 기존 사람답변을 최대 3개 찾습니다.
3. `enabled=TRUE`, `quality_state=USE`, `pii_scan=PASS`인 답변만 AI 근거로 사용합니다.
4. 기존 답변의 말투와 확인 절차만 참고하고 고객정보나 과거 주문상태는 복사하지 않습니다.
5. 현재 가격·재고·출고·배송·취소·환불 상태가 확인되지 않으면 단정하지 않고 `필수 확인`으로 남깁니다.
6. 초안은 `AI 답변`으로 표시해 사람답변과 분리 저장하고 2차 개인정보 검사를 거칩니다.
7. 사람이 쇼핑몰 원문과 주문·재고·정책을 확인한 뒤 직접 수정하고 전송합니다.
<callout icon="🤖" color="purple_bg">
	**현재 답변 참고 데이터**
	스마트스토어 3개월 기록에서 선별한 120개 사례가 등록되어 있습니다. 즉시 참고 가능한 `USE`와 사람이 추가 검토해야 하는 `REVIEW`가 구분되어 있습니다. 지그재그와 에이블리 답변은 앞으로 정상 수집된 사람답변이 쌓이면 같은 방식으로 추가됩니다.
</callout>

## 7. 복붙용 추천 프롬프트 {color="green"}
### A. 매일 기본 실행 · 오늘 새로 들어오거나 바뀐 문의
```text
마켓플레이스 CS 모니터 스킬로 오늘 접수되었거나 오늘 변화가 있는 문의를 수집해줘.
스마트스토어 4개 채널, 지그재그 주문문의·상품문의, 에이블리 문의관리를 모두 확인하고 구글시트에 동기화해.
답변이 필요한 문의에는 기존 사람답변 라이브러리를 참고해 AI 추천답변 초안도 만들어줘.
쇼핑몰에는 절대 답변을 전송하거나 상태를 변경하지 말고, 완료 후 채널별 건수·신규·변경·미응답·AI 초안·실패를 요약해줘.
```
### B. 현재 미답변 문의 전체 점검
```text
마켓플레이스 CS 모니터 스킬을 unanswered 모드로 실행해줘.
스마트스토어, 지그재그, 에이블리에서 현재 미답변이거나 열린 문의를 전부 확인하고 시트에 동기화해.
각 문의의 응답 필요 여부를 판정하고 AI 추천답변은 초안으로만 저장해.
답변 전송과 상담완료는 금지해. 톡톡 미읽음 문의는 상세 수집을 위해 열어도 되고, 읽음으로 바뀐 건수는 따로 보고해.
```
### C. 스마트스토어만 빠르게 점검
```text
마켓플레이스 CS 모니터 스킬로 스마트스토어만 확인해줘.
문의 관리, 고객문의 관리, 고객센터 문의 관리, 톡톡 상담에서 오늘 새로 생기거나 바뀐 문의를 수집하고 시트에 동기화해.
톡톡 미읽음 대화도 상세를 열어 전체 대화를 수집해도 돼. 읽음으로 바뀐 건수는 따로 보고해.
AI 추천답변은 생성하되 절대 전송하지 마.
```
### D. 지그재그와 에이블리만 점검
```text
마켓플레이스 CS 모니터 스킬로 지그재그 주문문의·상품문의와 에이블리 문의관리의 오늘 변화분만 확인해줘.
이번 실행에 지정한 로그인 브라우저를 정확히 확인하고, 답변이나 운영 상태 변경 없이 수집해.
시트 동기화 후 미답변 건과 수집 실패 건을 따로 정리해줘.
```
### E. AI 추천답변만 다시 만들기
```text
브라우저를 다시 수집하지 말고 현재 구글시트에서 답변이 필요한 문의만 확인해줘.
06_ANSWER_LIBRARY의 USE·PII PASS 사람답변을 최대 3개씩 참고하고 05_RULES를 적용해서 AI 추천답변을 다시 만들어줘.
사람답변과 AI 초안을 명확히 구분하고, 가격·재고·주문·배송·취소·환불 상태는 확인되지 않으면 단정하지 말고 필수 확인사항으로 남겨줘.
쇼핑몰 전송은 금지해.
```
### F. 기존 사람답변 라이브러리 갱신
```text
현재 시트의 답변완료 문의와 노션 3개월 CS 상담 운영 로그를 이용해 사람답변 라이브러리를 갱신해줘.
고객 질문과 실제 판매자 답변이 모두 있는 건만 사용하고, 단순 인사·자동메시지·AI 초안·개인정보 위험 건은 제외해.
기존 수동 USE/REVIEW/EXCLUDE 판단은 보존하고 06_ANSWER_LIBRARY에 중복 없이 반영한 뒤 추가·갱신·제외 건수를 보고해줘.
```
### G. 과거 특정 기간 보충 수집
```text
마켓플레이스 CS 모니터 스킬을 backfill 모드로 실행해줘.
조회 기간은 YYYY-MM-DD부터 YYYY-MM-DD까지야.
스마트스토어, 지그재그, 에이블리의 해당 기간 문의를 읽기 전용으로 수집하고 시트에 중복 없이 반영해.
이번 기간에 보이지 않는 기존 문의를 삭제로 처리하지 말고, 답변 전송이나 상태 변경도 하지 마.
```
### H. 실패한 채널만 재확인
```text
직전 CS 수집 결과에서 실패하거나 0건 검증이 불확실했던 채널만 다시 확인해줘.
직전 성공 채널은 재수집하지 말고, 로그인 만료·화면 구조 변경·실제 0건을 구분해.
쇼핑몰 쓰기 동작 없이 결과만 보고하고 정상 확인된 건만 시트에 동기화해.
```
### I. 수집 없이 현황 보고만 보기
```text
브라우저 수집이나 시트 변경 없이 현재 구글시트의 CS 현황만 읽어서 보고해줘.
미답변, AI 답변 준비, 검토 필요, 답변완료 건수와 최근 동기화 실패를 요약하고 지금 사람이 먼저 볼 문의를 알려줘.
```
## 8. 프롬프트를 직접 만들 때의 공식 {color="blue"}
아래 다섯 가지만 포함하면 됩니다.
```text
[대상] 어느 마켓과 채널을 볼지
[범위] 오늘 변화분 / 미답변 전체 / 특정 날짜
[처리] 수집만 / 시트 동기화 / AI 초안까지
[안전] 답변 전송·상태 변경 금지
[보고] 어떤 건수와 실패를 알려줄지
```
예시:
```text
스마트스토어 톡톡과 고객문의 관리의 오늘 변화분을 수집해 시트에 동기화하고, 미답변 건에 AI 초안을 만들어줘. 톡톡 읽음 전환은 허용하지만 답변 전송은 금지하고, 읽음 전환·처리시간·실패 건을 보고해줘.
```
## 9. 정상 완료 보고에서 확인할 항목 {color="green"}
- 7개 채널 중 실제로 시도한 채널과 건너뛴 이유
- 화면 표시 총건수와 수집·건너뜀 건수의 일치 여부
- `NEW / CHANGED / UNCHANGED / NEEDS_REPLY` 건수
- AI 추천답변 수와 참고답변 ID 유무
- 개인정보 1차·2차 검사 결과
- 시트 동기화 성공 여부와 실행 ID
- 금지된 쇼핑몰 쓰기 동작 `0건`
- 톡톡 상세 확인으로 발생한 미읽음→읽음 전환 건수
- 로그인 만료, CAPTCHA, 화면 구조 변경, 실제 0건 여부
## 10. 자주 생기는 상황 {color="orange"}
### Chrome과 Whale이 둘 다 열려 있을 때
이 노트북에서 두 브라우저를 병행 사용하기 때문에 생길 수 있는 환경 문제입니다. Whale을 일반적으로 금지하지 않고, 사용자가 이번 실행에서 지정한 브라우저의 실제 앱·프로필·URL·로그인 상태를 확인합니다. 브라우저를 지정하지 않으면 현재 기본인 Google Chrome을 사용합니다.
### 로그인 화면이 나왔을 때
Codex가 아이디나 비밀번호를 입력하지 않습니다. 사용자가 로그인·인증을 완료한 뒤 “로그인했어, 이어서 해줘”라고 입력합니다.
### 톡톡 미읽음 문의가 있을 때
이 설치에서는 미읽음 문의를 상세 수집하기 위해 열어도 됩니다. 읽음으로 바뀐 건수는 별도로 기록하며, 이 허용은 답변 전송·상담완료·태그·메모 변경까지 확대되지 않습니다.
### AI 추천답변이 없을 때
유사한 `USE` 답변이 없거나 필수 사실이 부족한 경우입니다. 운영 규칙만으로 보수적인 초안을 만들거나 사람 검토 대상으로 남깁니다.
### 5분마다 자동 실행하고 싶을 때
일반 프롬프트 한 번은 1회 실행입니다. 반복 실행은 별도의 Codex 예약 자동화를 만들어야 하며, 실행 시점에도 지정한 브라우저의 로그인 세션이 유지되어야 합니다. 로그인 만료·CAPTCHA는 사람이 처리해야 합니다.
## 11. Claude에서도 사용할 수 있나요? {color="purple"}
<callout icon="🧩" color="purple_bg">
	**확인 결론: 구조는 호환되지만 현재 Codex 설치본을 그대로 복사하는 것만으로는 전체 수집이 동작하지 않습니다.**
	Claude Code도 `SKILL.md`, 참고 파일, 실행 스크립트로 구성된 Agent Skills를 지원합니다. 다만 현재 설치본은 Codex 전용 브라우저 제어 이름과 `.codex` 절대 경로를 사용하므로 Claude용 포팅과 실제 로그인 브라우저 테스트가 한 번 필요합니다.
</callout>

### 그대로 재사용 가능한 부분
- `SKILL.md`의 `name`·`description` frontmatter와 Markdown 지침 구조
- `references/`의 채널 규칙, 보고 스키마, 답변 라이브러리, 시트 동기화 규칙
- `scripts/`의 Node.js 정규화·마스킹·중복 판정·답변 참고 데이터 처리 로직
- 답변 전송 금지, 톡톡 읽음 전환 별도 집계, `AUTO_SEND` 비활성화 같은 안전 경계

### Claude용으로 바꿔야 하는 부분
1. 전체 스킬 폴더를 개인 스킬 위치 `~/.claude/skills/marketplace-cs-monitor/`에 설치합니다.
2. `chrome:control-chrome` 지시를 Claude in Chrome 연결 방식으로 바꿉니다. Claude Code에서는 `claude --chrome` 또는 세션 안의 `/chrome`으로 연결하며, 공식 지원 브라우저는 Chrome과 Edge입니다.
3. Codex 설치 경로를 `${CLAUDE_SKILL_DIR}/...` 기준으로 바꿉니다.
4. 구글시트·노션을 Claude에서 직접 사용하려면 해당 MCP 또는 동기화 엔드포인트 접근을 별도로 연결합니다. 노션 MCP 예시는 `claude mcp add --transport http notion https://mcp.notion.com/mcp`입니다.
5. Claude에서는 `/marketplace-cs-monitor`로 호출하고, 실제 로그인 Chrome에서 7개 채널 수집·마스킹·시트 동기화를 다시 검증합니다.

### 현재 판정
- **Codex:** 전체 설치 및 스크립트 테스트 완료
- **Claude Code:** 형식 호환 확인 · 아직 Claude용 복사/경로 변환/브라우저 실사용 테스트는 하지 않음
- **Claude.ai 웹·모바일 채팅:** 로컬 `~/.claude/skills/`를 직접 읽지 않으므로 같은 방식으로는 사용할 수 없음. 계정에 별도로 업로드한 스킬과 연결된 도구가 필요함
